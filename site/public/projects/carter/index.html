Carter App.

The working day, connected.

MY ROLE

Senior Mobile Engineer · Danihel Group Inc. · 2025–2026

TECHNOLOGY / FOCUS

Flutter · Dart · Mobile field operations

01 / CONTEXT

From a booking to a completed job.

Carter connects assembly-service scheduling with the people carrying out the work. Managers coordinate orders through the wider platform; technicians use the mobile app to work through their assigned day, handle service requests and report progress.

The challenge is continuity: a schedule becomes a job, a job changes state, and those changes need to stay understandable to both field and office teams.

02 / CONTRIBUTION

Mobile engineering at Danihel Group.

Carter App is part of my Senior Mobile Engineer work at Danihel Group Inc. It is a separate product from my earlier RightCom queue-management work.

The portfolio focuses on the technician-facing mobile application and its place in the wider Carter platform. The administrative web application provides context for that relationship.

03 / ENGINEERING

A mobile client for a changing work day.

The local project uses Flutter and separates presentation, domain logic and data access. Its modules cover work-day schedules, work history, service support and product workflows, with API integration connecting the app to platform data.

Camera uploads, push notifications, maps and background location are integration points in the source project. These are product architecture details; they are not a claim that I independently authored every module.

03B / PRODUCT JOURNEY

Prepare. Work. Close the loop.

  1. Start the daySign in and review assigned work and upcoming schedules.
  2. Carry out the jobUse the order context and service tools needed in the field.
  3. Keep teams informedRecord progress and return updates to the operational platform.
